# Accessibility patterns (Impeccable)

Read the section for the pattern you are building. Each rule names the WCAG 2.2 criterion it serves. When unsure, take the platform default over a custom rebuild, and remove ARIA rather than add it.

## Dialogs and overlays

- Prefer `<dialog>` opened with `showModal()`: the background becomes inert and Escape closes it for free.
- A custom overlay sets `inert` on everything behind it, `role="dialog"` and `aria-modal="true"` on itself, and a name with `aria-labelledby` pointing at its heading.
- On open, move focus inside: the first field, or the dialog itself when it only shows content. On close, return focus to the control that opened it (2.4.3).
- Escape closes it. A click on the backdrop may close it; the keyboard path must not depend on that.

## Menus, tabs, listboxes, comboboxes

- Tab moves between widgets; arrow keys move inside one. Enter and Space activate. Home and End jump to the ends of a list (2.1.1).
- Roving tabindex: the active item has `tabindex="0"`, every other item `-1`, and arrow keys move both the `0` and the focus.
- A combobox keeps focus in its input and points `aria-activedescendant` at the highlighted option instead of moving focus.
- `aria-expanded` on the trigger tells whether the popup is open; `aria-selected` or `aria-checked` on items tells the state.

## Forms and validation

- Every control has a `<label for>` or a wrapping `<label>`. A placeholder is never a label (1.3.1, 3.3.2).
- Add a real `autocomplete` token (`email`, `tel`, `street-address`, `one-time-code`), the right `type` and `inputmode`, and never block paste.
- Validate on submit. Keep the submit button enabled; a disabled submit tells nobody what is missing.
- On error: `aria-invalid="true"` on each failing field, `aria-describedby` pointing at its error text, then move focus to the first failing field (3.3.1).
- The error text says what is wrong and how to fix it: "Nomor HP harus 10–13 digit", not "Input tidak valid".
- While the request runs, keep the button in place and announce the state; do not remove it from the tab order.

## Announcements

- Field-specific errors: `aria-describedby`, nothing else.
- Non-urgent updates not tied to a control (saved, 12 results, item added): a polite region, `role="status"`.
- Urgent errors not tied to a field: `role="alert"`, and only those.
- Render the region empty when the page loads, then change its text. A region inserted together with its message is often not announced (4.1.3).
- Toasts that carry an action or an error stay until dismissed.

## Route changes in a single-page app

A client-side navigation resets nothing. Update `document.title`, then move focus to the new view's `<h1>` (with `tabindex="-1"`) or `<main>`, so a screen-reader user hears that the page changed (2.4.2, 2.4.3).

## Hit areas and pointer

- Targets are at least 24×24 CSS px, or spaced so a 24px circle around each does not overlap another (2.5.8). Aim for 44×44 on touch where the density allows.
- Grow a small icon button's target with a pseudo-element instead of growing the icon; never let two extended targets overlap.
- Decorative layers over controls get `pointer-events: none`.
- Every drag has a single-pointer alternative: buttons or a menu that move the same item (2.5.7).

## Motion and time

- Wrap motion in `@media (prefers-reduced-motion: no-preference)`. Under reduced motion, swap slides and scales for a short cross-fade; drop parallax and autoplay (2.3.3).
- Anything that moves, blinks, or updates by itself for more than 5 seconds gets a visible pause control (2.2.2).
- Nothing the user needs disappears on a timer.

## Focus rings

- Style `:focus-visible`, not `:focus`. Prefer the browser's own ring; adding `outline-offset` keeps it.
- A custom ring uses a project token and reaches 3:1 against every color it crosses (1.4.11). `outline: none` is only allowed next to a replacement you checked in the render.
- A focused element is never fully covered by a sticky header, footer, or cookie bar (2.4.11). Give the scroller `scroll-padding-top` equal to the sticky bar's height.
- A "skip to content" link is the first focusable element when navigation comes before `<main>`.

## Verify

`python ~/.claude/skills/uicheck/scripts/check.py <url> --a11y` measures zoom lock, tab order, keyboard reach, visible focus, and covered focus. It cannot hear a screen reader: names, roles, and announcements are read from the code. Report what you could not run as `not verified`.
